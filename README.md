# download-speed-meter

Консольный скрипт на Node.js, который измеряет скорость скачивания по адресу:

1. делает к адресу 10 GET-запросов **строго последовательно** и дожидается полного ответа на каждый;
2. считает **среднее время запроса** и **общий объём скачанных данных**;
3. печатает **скорость скачивания** в **Мбит/с**.

Внешних зависимостей нет: только встроенные в Node.js `fetch`, `node:util` и `node:test`.

## Требования

- Node.js **20 или новее** (проверено на 24). Если стоит nvm, в репозитории есть `.nvmrc`: выполните `nvm use`.
- `npm install` не нужен.

## Запуск

```bash
git clone https://github.com/KuliyevMerdan/download-speed-meter.git
cd download-speed-meter
node index.js "https://speed.cloudflare.com/__down?bytes=10000000"
```

URL лучше брать в кавычки: в zsh и bash символы `?` и `&` иначе обрабатываются оболочкой.

Можно передать любой адрес, например тяжёлую картинку:

```bash
node index.js "https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg"
```

То же через npm: `npm start -- "<url>"`.

### Опции

| Флаг | По умолчанию | Что делает |
| --- | --- | --- |
| `-n`, `--count <N>` | `10` | сколько запросов сделать |
| `-h`, `--help` | | показать справку |

Если запрос завершился ошибкой (не 2xx, DNS, отказ соединения), скрипт пишет номер запроса и причину и выходит с кодом `1`.

## Единицы измерения

| Величина | Единица | Пояснение |
| --- | --- | --- |
| Скорость | **Мбит/с** (`Mbit/s`) | мегабиты в секунду, 1 Мбит = 1 000 000 бит. В этих единицах скорость указывают провайдеры и speedtest-сервисы, так что результат легко сравнить с тарифом. В скобках то же значение в МБ/с (Мбит/с ÷ 8). |
| Объём | `B`, `kB`, `MB`, `GB` | десятичные: 1 kB = 1000 байт, 1 MB = 1 000 000 байт. Рядом печатается точное число байт. |
| Время | `ms` / `s` | миллисекунды, а от 1 секунды и больше секунды. |

## Как считается

- **Время запроса**: от отправки запроса до получения последнего байта тела ответа (`performance.now()`). Сюда входит и ожидание ответа сервера, и чтение всего тела.
- **Объём**: сумма байт тела ответа, без HTTP-заголовков. Тело читается потоком, кусками: в памяти файл целиком не держится, поэтому подходят и большие файлы.
- **Среднее время** = сумма времён всех запросов / число запросов.
- **Скорость** = общий объём × 8 / суммарное время всех запросов. Это не среднее скоростей отдельных запросов: при таком усреднении быстрые запросы весили бы больше, чем им положено (см. тест `summarize` в `test/measure.test.js`).
- Запрос уходит с `Accept-Encoding: identity`, чтобы сервер не сжимал ответ: так считаются байты, которые реально пришли по сети, а не распакованные.
- `fetch` переиспользует соединение (keep-alive), поэтому первый запрос обычно дольше остальных: в нём есть DNS, TCP и TLS. Это видно в построчном выводе.

## Тесты

```bash
npm test
```

Тесты не ходят в интернет: они поднимают локальный HTTP-сервер и проверяют, что

- тело читается целиком и считается правильно;
- ответы не 2xx превращаются в понятную ошибку;
- скорость считается как «весь объём / всё время»;
- CLI делает ровно N запросов и никогда не шлёт их параллельно;
- на неверный URL и упавший запрос CLI выходит с кодом 1 и объясняет причину.

## Структура

```
index.js              CLI: разбор аргументов, цикл из N запросов, вывод
lib/measure.js        один запрос, подсчёт итогов, форматирование чисел
test/measure.test.js  тесты на встроенном node:test
```

## Что бы улучшил, будь больше времени

- Разбить время запроса на этапы: DNS, TCP, TLS, время до первого байта (TTFB) и само скачивание. Сейчас это одно число.
- Показывать медиану, минимум, максимум и разброс, а не только среднее: одно медленное скачивание сильно сдвигает среднее.
- Таймаут на запрос и повтор упавших запросов, чтобы одна сетевая ошибка не обрывала всю серию.
- Режим «холодных» запросов, с новым соединением на каждый запрос, чтобы сравнить с keep-alive.
- Прогресс-бар для тяжёлых файлов на медленном канале.
- Вывод в JSON (`--json`) для скриптов и CI.
- Предупреждать, когда ответ отдаёт кэш CDN (заголовки `Age`, `CF-Cache-Status`, `X-Cache`): повторные запросы тогда меряют ближайший узел CDN, а не исходный сервер.
